# Push-уведомления Niet Café — настройка (≈15 минут, один раз)

**Что получится:** уведомления приходят на телефон даже при закрытом приложении и **заблокированном экране** — со звуком и вибрацией, как сообщение из мессенджера. Нажатие на уведомление открывает приложение.

| Кому | Что приходит |
|---|---|
| Кухня / Бар | 🔔 новый заказ · ❌ отмена позиции · ⛔ блюдо ушло в автостоп / ✅ снова в меню |
| Официант | 👍 принято · ✅ готово (по своим заказам) · 🙋 вызов · 🧾 просят счёт · 📱 заказ со стола · 🛵 доставка · 🥡 самовывоз · ⛔ стоп |
| Руководитель | 🛵 доставка · 🥡 самовывоз · ⛔ автостоп / ✅ снова в меню · ⚠ продукт заканчивается |
| Склад | ⚠ продукт заканчивается (остаток стал ниже минимума) · ⛔ автостоп |
| Гость (доставка / самовывоз) | статус заказа: принят → готовится → готов / курьер едет → доставлен. Гость сам нажимает «🔔 Сообщить о статусе на телефон» |

Если приложение открыто на экране — работает как раньше (окно + свой звук), системное уведомление не дублируется.

> **Push уже был настроен раньше (7_push.sql)?** Тогда нужны только: **Шаг 2** (обновить код функции `push`), **Шаг 3б** (`33_push_all.sql`), **Шаг 4** и **Проверка**.

## Шаг 1. Ключи
Откройте `vapid-keys.html` двойным щелчком → «Создать ключи». Получите **публичный** и **приватный** ключ.
Публичный вставьте в **два** файла: `index.html` (`const VAPID='…'`) и `guest.html` (`const GVAPID='…'`).
Сейчас там уже стоит ключ — если вы его создавали и приватный ключ у вас, этот шаг пропустите.

## Шаг 2. Edge Function
Supabase → **Edge Functions** → функция `push` (или **Deploy a new function** с именем `push`) → вставьте **весь** код из `supabase/functions/push/index.ts` → Deploy.
**Обязательно выключите «Verify JWT»** (защита — секрет, шаг 3).

**Edge Functions → Secrets** — четыре значения (если уже добавлены — не трогайте):

| Имя | Значение |
|---|---|
| `VAPID_PUBLIC` | публичный ключ |
| `VAPID_PRIVATE` | приватный ключ |
| `VAPID_SUBJECT` | `mailto:ваш@email.kz` |
| `PUSH_SECRET` | любая длинная случайная строка (придумайте сами) |

## Шаг 3. База данных
**3а.** SQL Editor → выполните `7_push.sql` целиком (если не выполняли раньше). Затем отдельным запросом впишите тот же секрет:

```sql
update push_cfg set val='ТОТ_ЖЕ_PUSH_SECRET' where key='secret';
```

**3б.** Выполните `33_push_all.sql` целиком (можно повторно).

## Шаг 4. Выложите обновлённые `index.html`, `guest.html`, `sw.js`

## Шаг 5. Включите на каждом телефоне сотрудника
Войдите под сотрудником → кнопка **🔊** в шапке → **«🔔 Включить уведомления»** → **Разрешить**.
Затем там же **«🔒 Проверить на заблокированном экране»** → сразу заблокируйте телефон → через 15 секунд должно прийти «🔔 Проверка уведомлений».

- **iPhone/iPad (нужен iOS 16.4+):** сначала в Safari «Поделиться» → **«На экран Домой»**, открывайте приложение **только с иконки**, потом включайте. В обычной вкладке Safari push на iPhone не работает.
  Настройки iPhone → Уведомления → Niet Café → включите «Заблокированный экран», «Баннеры», «Звуки».
- **Android (Chrome):** работает и из вкладки, но лучше установить: меню ⋮ → «Установить приложение».
  Настройки → Приложения → Chrome → Уведомления — включены, на заблокированном экране «показывать всё».
  Настройки → Батарея → Chrome → **«Без ограничений»** — иначе Samsung/Xiaomi/Huawei «усыпляют» уведомления.
- **«Не беспокоить» / «Фокус»** глушит звук — добавьте Chrome/Niet Café в исключения.
- Нажали «Блокировать» — разрешите уведомления в настройках браузера для сайта.
- На общем планшете: при «Выйти» подписка устройства снимается, следующий сотрудник включит свою.

Руководитель видит, у кого push работает: **Сотрудники → колонка «Push на телефон»** (устройство и когда последнее уведомление дошло; «🔕 нет» — сотрудник ещё не включил).

## Проверка из базы
```sql
select push_send('[{"kind":"test","to_role":"waiter","tag":"test","title":"Тест","body":"Push работает"}]'::jsonb);
```
Придёт всем официантам с включёнными уведомлениями (можно `"to_roles":["boss","store"]`).

## Если не приходит
**Самое быстрое:** выполните в SQL Editor файл `35_push_check.sql`, подождите 10 секунд и выполните `select * from push_check();` — таблица покажет, на каком шаге проблема и что сделать.

1. В приложении «Проверить» пишет «Push-сервер ещё не настроен» — не вписан секрет (шаг 3а).
2. Edge Functions → `push` → **Logs**: нет записей — не совпадает секрет (`push_cfg` и `PUSH_SECRET`) или включён Verify JWT. Ошибка 403 — тоже секрет.
3. Сотрудники → «Push на телефон» показывает ⚠ — отправка с ошибкой: проверьте ключи VAPID (публичный в html = `VAPID_PUBLIC`).
4. Ключи VAPID пересоздавали — на каждом телефоне «Выключить» → «Включить».
5. Приходит при открытом экране, но не на заблокированном — это настройки телефона (батарея, «Не беспокоить», уведомления на экране блокировки), см. шаг 5.

Сбой отправки никогда не мешает принимать заказы: все ошибки push в базе подавляются.
Демо-данные (31) и сброс (32) уведомлений не рассылают.

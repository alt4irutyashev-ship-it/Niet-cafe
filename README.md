### Обновление 27.11.2026: надёжность заказов и склада
1. SQL Editor → `49_fixes.sql` (можно повторно). В конце покажет, сколько двойных заказов нашёл и объединил. 2. Выложить `index.html`, `sw.js` (niet-v35).

- **Один заказ на стол.** Раньше, если официант добавлял блюдо в ту же секунду, когда принималась заявка гостя (или работали два официанта), на столе открывалось два заказа — часть блюд не попадала в чек. Теперь база этого не допускает; уже задвоенные заказы объединены.
- **Номера выноса и доставки** не повторяются при одновременном приёме заявок.
- **Перенос стола** — одной операцией на сервере; если стол заняли в этот момент, заказы объединятся.
- **Средневзвешенная цена.** При приходе цена продукта = (остаток × старая цена + приход × цена прихода) / новый остаток. Пример: 10 кг по 5 900 + 2 кг по 6 500 → 6 000 ₸/кг. Если остатка нет (0 или минус) — берётся цена прихода. В приходах и накладных остаётся фактическая цена; себестоимость уже проданных блюд не меняется.
- **Опасные скрипты** перенесены в папку `_осторожно/`. Сброс статистики (32) работает только после одноразового разрешения, демо (31) не загрузится, если есть настоящие закрытые заказы.

### Доставка и самовывоз (шаги 21–22)
1. SQL Editor → выполнить `21_delivery.sql`, затем `22_nutrition.sql` (оба можно запускать повторно).
2. Выложить `index.html`, `guest.html`, `order.html`, `sw.js` (версия уже поднята до niet-v7).
3. Ссылка для Instagram / 2ГИС / WhatsApp: адрес сайта + `/order.html` (видна во вкладке «Гостям»).

Как работает:
- гость собирает корзину, выбирает «Самовывоз» или «Доставка», указывает имя, телефон и (для доставки) адрес;
- доставка **990 ₸**, если заказ меньше **5 000 ₸**, иначе бесплатно (суммы меняются в «Затраты → Настройки»); 10% обслуживания не берётся;
- у официанта всплывает уведомление (и push): блюда, сумма, имя, телефон (нажимается — звонок), адрес;
- официант нажимает «Подтвердить» → заказ становится «Доставка-N» или «Вынос-N» и уходит на кухню и бар;
- со склада продукты списываются **один раз**, когда кухня/бар отмечает «готово» (или при закрытии заказа, если «готово» не отмечали), с учётом % потерь: брутто = нетто ÷ (1 − потеря%). Одинаково для зала, выноса и доставки.
- защита: цены берутся из меню, а не с телефона; блюда на стопе не принимаются; не больше 3 заявок с одного номера за 10 минут.

### КБЖУ и аллергены
Заполнены для всех блюд. Если у блюда полная техкарта — КБЖУ считается по ней, иначе типовые значения порции.
Если техкарта явно неполная, в «Меню» у блюда появляется красная подсказка. Ручная правка КБЖУ отключает автопересчёт
(кнопка «Считать по техкарте» возвращает его). Гости видят ккал на карточке, КБЖУ и аллергены на странице блюда
и могут скрыть блюда с нужными аллергенами. Значения ориентировочные — у гостей стоит пометка «≈».

## Установка

1. Supabase → SQL Editor: если база новая — выполнить `1_schema.sql`, затем `2_menu.sql`.
2. Выполнить `4_update.sql`, `5_guest.sql`, затем `6_update.sql` (их можно запускать повторно).
3. В `index.html` и `guest.html` вписать адрес и ключ Supabase в строке `const URL_=…,KEY=…`
   (Project Settings → API: Project URL и anon public key).
4. В Supabase → Authentication отключить подтверждение email (вход по логинам `@niet.cafe`).
5. Загрузить ВСЕ файлы в GitHub (включая sw.js, manifest и иконки) — Render обновит сайт.
   При следующих обновлениях сайта увеличьте версию в первой строке `sw.js` (niet-v1 → niet-v2), чтобы телефоны подхватили новое.
6. По желанию: положить логотип в репозиторий как `logo.png` — он появится на гостевой странице.

## Что умеет

**Официант** — схема зала (9 столов, вход справа сверху), заказ, комментарии к блюдам для кухни,
10% обслуживания, пречек, перенос и объединение столов, оплата наличными / картой / Kaspi / смешанная,
уведомление «блюдо готово», стоп-лист.

**Кухня и бар** — заказы карточками по столам (краснеют через 15 мин), комментарии, техкарты, стоп-лист.

**Склад** — остатки, приход, выдача, списание с причиной, инвентаризация, минимальные остатки, журнал.

**Руководитель** — отчёты (выручка, обслуживание, прибыль, средний чек, оплаты, официанты, по часам и
дням недели, «заканчивается»), заказы, меню (цены, новые блюда, состав, фото, стоп), техкарты с
себестоимостью и фудкостом, вкладка «Гостям» (ссылки TikTok / Instagram / WhatsApp / 2ГИС и ссылка для
NFC), склад, сотрудники, затраты.

**Язык** — переключатель РУС / ҚАЗ.

## Гостевая страница (NFC)

Ссылка: адрес сайта + `/guest.html` (её видно во вкладке «Гостям» у руководителя).
Записать на метку: приложение NFC Tools → Записать → URL. Одна ссылка подходит для всех столов,
её же можно сделать QR-кодом.

### Ссылки на столы
У каждого стола своя ссылка `guest.html?t=НОМЕР` (готовый список — у руководителя во вкладке «Гостям»).
По ней гость может позвать официанта, попросить счёт и отправить заказ — у официанта сразу всплывает уведомление.
Общая ссылка без номера — просто меню (для QR на входе или в Instagram).

## Без интернета
Официант продолжает принимать заказы: они копятся в очереди и отправляются сами, когда связь вернётся.
Оплата и закрытие стола — только с интернетом. Гости видят меню, если уже открывали его раньше.


`qr.js` — генератор QR-кода для пречека (библиотека QRCode, MIT). Загружать на Render вместе с index.html.
